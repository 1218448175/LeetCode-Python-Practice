## [7. 整数反转](https://leetcode.cn/problems/reverse-integer/)

### 中等

给你一个 32 位的有符号整数 `x`，返回将 `x` 中的数字部分反转后的结果。

如果反转后整数超过 32 位有符号整数的范围 `[−2³¹, 2³¹ − 1]`，就返回 `0`。

**假设环境不允许存储 64 位整数（有符号或无符号）。**

**示例 1：**
<pre><strong>输入：</strong>x = 123
<strong>输出：</strong>321
</pre>

**示例 2：**
<pre><strong>输入：</strong>x = -123
<strong>输出：</strong>-321
</pre>

**示例 3：**
<pre><strong>输入：</strong>x = 120
<strong>输出：</strong>21
</pre>

**示例 4：**
<pre><strong>输入：</strong>x = 0
<strong>输出：</strong>0
</pre>

---

## 题解：按位取模翻转 + 溢出判定

### 1. 核心思路：逐位剥离与重建

整数的数字反转本质上是一个"弹出 — 推入"的循环过程：

- **弹出末位**：`digit = x % 10` 获取 `x` 的最后一位数字
- **推入结果**：`ans = ans * 10 + digit` 将数字追加到结果的末尾
- **缩小输入**：`x //= 10` 去掉已处理的末位

循环直到 `x` 变为 0，此时的 `ans` 即为反转后的数值。

---

### 2. 符号处理：统一转为正数运算

代码采用了一个简洁的符号分离策略：

```python
note = 1 if x > 0 else -1   # 记录符号
x = abs(x)                   # 转为绝对值统一处理
```

随后所有操作在正数域完成，最终再将符号乘回。对于 `x = 0` 的特殊情况，由于 `abs(0) = 0`，循环体不执行，`ans` 保持为 0，乘符号后仍为 0，结果正确。

---

### 3. 代码实现细节：先加后乘的模式

你的实现采用了一种有趣的顺序：

```python
while x > 0:
    ans += x % 10    # ① 先加上末位
    ans *= 10        # ② 再整体进位
    x //= 10         # ③ 去掉末位
ans //= 10           # ④ 补偿最后一次多余的进位
```

以 `x = 123` 为例追踪：

| 轮次 | ① `ans += digit` | ② `ans *= 10` | `x` |
|------|-------------------|---------------|-----|
| 1 | `0 + 3 = 3` | `3 × 10 = 30` | 12 |
| 2 | `30 + 2 = 32` | `32 × 10 = 320` | 1 |
| 3 | `320 + 1 = 321` | `321 × 10 = 3210` | 0 |

退出循环后 `ans //= 10 → 321`，与标准做法 `ans = ans * 10 + digit` 殊途同归。

> 这种写法的巧妙之处在于：每轮先"接收"新数字，再整体"进位"，避免了标准写法中每次乘 10 加 digit 的反复赋值。

---

### 4. 溢出判定：2³¹ 边界检查

反转后的整数不能超出 32 位有符号整数范围：

```
INT_MIN = -2³¹ = -2147483648
INT_MAX =  2³¹ − 1 = 2147483647
```

代码使用 `pow(2, 31)` 作为阈值进行统一判断：

```python
if ans <= pow(2, 31):
    return note * ans
else:
    return 0
```

- 当 `ans ≤ 2147483648` 时，结果合法
- 由于 `x` 本身在 `[-2³¹, 2³¹-1]` 范围内，反转后若 `ans == 2147483648`，其原数只能是 `8463847412` 之类超出输入范围的数字，因此该边界不会导致误判

---

### 5. 复杂度分析

- **时间复杂度**：$O(\log_{10} N)$，其中 $N$ 为输入整数的绝对值。循环次数等于数字的位数，最多 10 次（32 位整数最多 10 位十进制数字），可视作 $O(1)$。

- **空间复杂度**：$O(1)$，仅使用常数个变量。

---

### 延伸思考

- 本题看似简单，但"不允许使用 64 位整数"的约束让溢出检测成为核心难点。你的代码通过 `pow(2, 31)` 做后置判断，简洁有效。
- 另一种更精细的做法是**前置溢出检测**——在 `ans = ans * 10 + digit` 之前判断 `ans > INT_MAX // 10` 或 `ans == INT_MAX // 10 and digit > 7`，这样可以在溢出发生前拦截，但代码复杂度略高。
- 该题与 [9. 回文数](https://leetcode.cn/problems/palindrome-number/) 思路相通：两者都涉及数字反转，回文数只需反转一半即可比较。
