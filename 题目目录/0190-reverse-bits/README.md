## [190. 颠倒二进制位](https://leetcode.cn/problems/reverse-bits/)

### 简单

颠倒给定的 32 位无符号整数的二进制位。

**示例 1：**

<pre><strong>输入：</strong>n = 00000010100101000001111010011100
<strong>输出：</strong>964176192 (00111001011110000010100101000000)
<strong>解释：</strong>输入的二进制串 <strong>00000010100101000001111010011100</strong> 表示无符号整数 <strong>43261596</strong>，
     因此返回 964176192，其二进制表示形式为 <strong>00111001011110000010100101000000</strong>。</pre>

**示例 2：**

<pre><strong>输入：</strong>n = 11111111111111111111111111111101
<strong>输出：</strong>3221225471 (10111111111111111111111111111111)
<strong>解释：</strong>输入的二进制串 <strong>11111111111111111111111111111101</strong> 表示无符号整数 <strong>4294967293</strong>，
     因此返回 3221225471，其二进制表示形式为 <strong>10111111111111111111111111111111</strong>。</pre>

**提示：**

- 输入是一个长度为 32 的二进制字符串

**进阶：**

- 如果多次调用这个函数，你将如何优化你的算法？

## 题解：分治法 — 二分反转位

### 1. 核心思路：自底向上的位交换

如果将 32 位二进制位视为一个整体，反转的直观做法是：**第 0 位与第 31 位交换，第 1 位与第 30 位交换...以此类推**。但逐位交换需要 16 次操作，且每次都需要提取两个对称位。

我们可以用**分治法**更高效地完成：从相邻位开始，逐步扩大交换范围，经过 5 轮操作（1→2→4→8→16 位间隔）即可完成全部 32 位的反转。这就像**将一张纸不断对折，每一折的位置刚好被翻转**。

```
原始：    a b c d e f g h ...
第1轮：   b a d c f e h g ...  (交换相邻1位)
第2轮：   d c b a h g f e ...  (交换相邻2位)
第3轮：   h g f e d c b a ...  (交换相邻4位)
第4轮：   (交换相邻8位)
第5轮：   (交换相邻16位)
```

每一轮的本质是：**把相邻的两组位看作一个整体，交换这两组的位置**。

---

### 2. 执行逻辑的详细拆解

核心是 5 个掩码常量，分别对应 5 轮交换：
- `m₀ = 0x55555555` → `0101 0101 ...` → 提取奇数位
- `m₁ = 0x33333333` → `0011 0011 ...` → 以 2 位为一组，提取低半组
- `m₂ = 0x0f0f0f0f` → `0000 1111 ...` → 以 4 位为一组，提取低半组
- `m₃ = 0x00ff00ff` → `0000 0000 1111 1111 ...` → 以 8 位为一组，提取低半组
- `m₄ = 0x0000ffff` → 低 16 位全为 1 → 提取低 16 位

> **Python 无符号右移须知**：Python 的 `int` 是任意精度整数，`>>` 不会自动截断到 32 位。但代码中使用掩码主动提取有效位后再组合，天然确保结果在 32 位范围内，无需最后 `& 0xFFFFFFFF`。这是本代码与常见 Python 写法的一个精妙差别。

#### 第1轮：交换相邻位（间隔 1 位）

```python
n = n >> 1 & m0 | (n & m0) << 1
```

分解来看：
- `n >> 1 & m0`：右移 1 位后用 m₀ 掩码，**取出原本偶数位向右移动后的值**
- `(n & m0) << 1`：用 m₀ 掩码提取奇数位后左移 1 位，**让奇数位移到偶数位的位置**
- 两者按位或：完成相邻位交换

> 为什么不是 `(n & 0xAAAAAAAA) >> 1 | (n & 0x55555555) << 1` 的写法？因为**先移后掩**可以复用 m₀ 这一个掩码，代码更简洁。两者的结果等价。

#### 第2轮：交换相邻 2 位组（间隔 2 位）

```python
n = n >> 2 & m1 | (n & m1) << 2
```

此时 `m₁ = 0x33333333`（`0011 0011 ...`）。每次以 2 位为一组，交换相邻的两组。

#### 第3轮：交换相邻 4 位组（间隔 4 位）

```python
n = n >> 4 & m2 | (n & m2) << 4
```

`m₂ = 0x0f0f0f0f`（`0000 1111 ...`）。每次以 4 位为一组，交换相邻的两组。

#### 第4轮：交换相邻 8 位组（间隔 8 位）

```python
n = n >> 8 & m3 | (n & m3) << 8
```

#### 第5轮：交换相邻 16 位组（间隔 16 位）

```python
return n >> 16 | (n & m4) << 16
```

最后一轮不需要掩码提取低半组后再右移——`n >> 16` 天然得到高 16 位移到低 16 位；而 `(n & m4) << 16` 提取低 16 位移到高 16 位，两者相或即完成最终反转。

---

### 3. 逻辑亮点

- **分治的层次感**：从 1 位 → 2 位 → 4 位 → 8 位 → 16 位，每一步的掩码都是上一步掩码分组宽度的两倍。这是一个非常经典的**二分翻转**模板，也适用于任意位数的整数反转。

- **掩码复用**：由于采用了 `先移后掩` 的策略，只需 5 个掩码常量，避免了常见的 `0xAAAAAAAA` / `0xCCCCCCCC` 等对偶掩码的声明，代码更紧凑。

- **Python 无需截断**：因为掩码天然只操作低 32 位，高位不受污染。这也是代码可以省略 `& 0xFFFFFFFF` 的原因。

- **O(1) 时间**：无论输入值是多少，都执行固定的 5 轮位操作，没有任何循环或分支。

---

### 4. 复杂度分析

- **时间复杂度**：$O(1)$。固定的 5 步位运算，与输入无关。

- **空间复杂度**：$O(1)$。仅使用常数个掩码变量，无额外内存分配。

---

### 5. 对比逐位遍历法

另一种常见解法是逐位遍历 32 次：

```python
class Solution:
    def reverseBits(self, n: int) -> int:
        ans = 0
        for i in range(32):
            ans |= ((n >> i) & 1) << (31 - i)
        return ans
```

此法时间复杂度 $O(32) = O(1)$，但**常数因子较大**（32 次循环 × 每次多步位操作）。分治法只需 5 步操作，在实际运行效率上更优，也更能体现对底层位的深刻理解。

### 代码回顾

```python
m0 = 0x55555555
m1 = 0x33333333
m2 = 0x0f0f0f0f
m3 = 0x00ff00ff
m4 = 0x0000ffff

class Solution:
    def reverseBits(self, n: int) -> int:
        n = n >> 1 & m0 | (n & m0) << 1
        n = n >> 2 & m1 | (n & m1) << 2
        n = n >> 4 & m2 | (n & m2) << 4
        n = n >> 8 & m3 | (n & m3) << 8
        return  n >> 16 | (n & m4) << 16
```

> **延伸思考**：此题的分治思想也与 **快速傅里叶变换（FFT）中的蝶形运算** 有异曲同工之妙——都是通过多轮、以 2 的幂次为跨度的交换，在 O(log n) 轮内完成整体反转。这也是位运算分治法的经典应用之一。
