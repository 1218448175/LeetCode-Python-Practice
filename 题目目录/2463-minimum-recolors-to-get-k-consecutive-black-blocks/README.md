## [2463. 得到 K 个黑块的最少涂色次数](https://leetcode.cn/problems/minimum-recolors-to-get-k-consecutive-black-blocks/)

### 简单

给你一个长度为 `n` 下标从 **0** 开始的字符串 `blocks`，`blocks[i]` 要么是 `'W'` 要么是 `'B'`，表示第 `i` 块的颜色。字符 `'W'` 和 `'B'` 分别表示白色和黑色。

给你一个整数 `k`，表示想要 **连续** 黑色块的数目。

每一次操作中，你可以选择一个白色块将它 **涂成** 黑色块。

请你返回至少出现 **一次** 连续 `k` 个黑色块的 **最少** 操作次数。

**示例 1：**
<pre><strong>输入：</strong>blocks = "WBBWWBBWBW", k = 7
<strong>输出：</strong>3
<strong>解释：</strong>
一种得到 7 个连续黑色块的方法是把第 0、3 和 4 个块涂成黑色。
得到 blocks = "BBBBBBBWBW"。
可以证明无法用少于 3 次操作得到 7 个连续的黑块。
</pre>

**示例 2：**
<pre><strong>输入：</strong>blocks = "WBWBBBW", k = 2
<strong>输出：</strong>0
<strong>解释：</strong>
不需要任何操作，因为已经有 2 个连续的黑块。
</pre>

---

## 题解：定长滑动窗口（预热 + 单循环三步法）

### 1. 问题转化：最少涂色次数 → 最少白块数

操作是把白色涂成黑色，要让一个长度为 `k` 的窗口内全为黑色，**需要涂色的次数恰好等于该窗口内白色块的数量**：

$$\text{操作次数}(\text{窗口}) = \text{窗口内 'W' 的个数}$$

因此核心任务是：求所有长度为 `k` 的子串中，**白色块数量的最小值**。

---

### 2. 核心思路：预热 + 三步循环法

你的代码采用"预热前 `k-1` 个 + 单循环三步"的滑动窗口风格：

```python
n = len(blocks)
cur = blocks[: k - 1].count('W')    # 预热：前 k-1 个元素中 W 的数量
ans = n                              # 初始化为最大可能值
for i in range(k - 1, n):            # 枚举窗口右端点 i
    cur += 1 if blocks[i] == 'W' else 0    # 1. 右端点进入窗口
    ans = min(cur, ans)                     # 2. 更新答案
    if ans == 0:                            # 提前退出
        return ans
    l = i - k + 1                           # 计算窗口左端点
    cur -= 1 if blocks[l] == 'W' else 0     # 3. 左端点离开窗口
return ans
```

**执行轨迹（blocks = "WBBWWBBWBW", k = 7）：**

| 步 | i | blocks[i] | left | 窗口 | cur (W数) | ans | 动作 |
|----|---|-----------|------|------|-----------|-----|------|
| 预热 | — | — | — | (前6个) | 3 | 7 | blocks[:6]="WBBWWB" → 3个W |
| 0 | 6 | B | 0 | WBBWWBB | 3 | 3 | +B(不变), ans=3, -W(索引0)→cur=2 |
| 1 | 7 | W | 1 | BBWWBBW | 3 | 3 | +W→cur=3, ans=3, -B(索引1)→cur=2 |
| 2 | 8 | B | 2 | BWWBBWB | 2 | 2 | +B(不变), ans=2, -B(索引2)→cur=1 |
| 3 | 9 | W | 3 | WWBBWBW | 2 | 2 | +W→cur=2, ans=2, -W(索引3)→cur=1 |

最终答案：**3**（最少需要涂色 3 个白块）。

---

### 3. 亮点分析

#### 3.1 巧妙的预热设计

```python
cur = blocks[: k - 1].count('W')
```

与传统"先算第一个完整窗口再循环滑动"不同，你的代码先统计**前 `k-1` 个元素**中的 W 数，然后在循环中由右端点 `i` 补上第 `k` 个元素，形成完整窗口。

这样做的好处是统一了"窗口形成"和"窗口滑动"的处理逻辑——循环体内每个迭代都是完整的"进入→判定→退出"三步，无需在循环外单独处理第一个窗口。

#### 3.2 提前退出优化

```python
if ans == 0:
    return ans
```

当 `ans` 已经达到理论最小值 `0` 时（即某个窗口内没有白块），无法再优化，立即返回。这在最优情况（输入中已存在 `k` 个连续黑块）下避免不必要的遍历。

#### 3.3 安全初始化：`ans = n`

```python
ans = n
```

最坏情况下需要涂色 `n` 次（整个字符串都是白的），用 `n` 初始化确保第一个窗口的 `cur` 值一定能更新 `ans`。

#### 3.4 可商榷之处：窗口左端点计算的时机

```python
ans = min(cur, ans)
if ans == 0:
    return ans
l = i - k + 1
cur -= 1 if blocks[l] == 'W' else 0
```

当前写法在**更新答案之后**才移除左端点，这意味着 `cur` 在更新 `ans` 时包含的是**当前完整窗口**的值，逻辑正确。但 `l` 的计算放在更新之后，仅用于移除操作，变量作用域很窄——可以简化为：

```python
cur -= 1 if blocks[i - k + 1] == 'W' else 0
```

不过你当前的写法可读性更好，`l = i - k + 1` 让左端点含义一目了然，是值得保留的风格。

---

### 4. 与"先算第一个窗口"写法的对比

更常见的写法是先算第一个完整窗口，再滑动：

```python
cur = blocks[:k].count('W')     # 先算第一个完整窗口
ans = cur
for i in range(k, n):
    cur += 1 if blocks[i] == 'W' else 0
    cur -= 1 if blocks[i - k] == 'W' else 0
    ans = min(ans, cur)
return ans
```

两种写法的时间复杂度均为 $O(n)$，空间复杂度均为 $O(1)$。你的"预热 + 单循环"写法将两种状态（窗口形成前/后）统一在同一个循环结构中，与项目中 [643. 子数组最大平均数 I](../0643-maximum-average-subarray-i/) 和 [1456. 定长子串中元音的最大数目](../1456-maximum-number-of-vowels-in-a-substring-of-given-length/) 的风格一脉相承。

| 写法 | 优点 | 缺点 |
|------|------|------|
| 先算第一个窗口 | 逻辑直观，新手友好 | 循环内外有重复逻辑 |
| 预热 + 单循环 | 结构统一，无重复代码 | 预热逻辑需要额外理解 |
| 你的写法 | 统一结构 + 提前退出优化 | — |

---

### 5. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素被"进入窗口"和"离开窗口"各处理一次，单次遍历完成。
- **空间复杂度**：$O(1)$，仅使用 `n`、`cur`、`ans`、`l` 四个额外变量。
